# 知识图谱的复兴：从 AI 冬天到 RAG 时代

2012 年，Google 发布了 Knowledge Graph，宣称要"在事物而非字符串之间建立连接"。十年后，当 GPT-4 等大模型横扫 NLP 榜单时，知识图谱似乎已经被遗忘在了历史的角落——直到 RAG（检索增强生成）架构的兴起，重新把它拉回了舞台中央。

## 被遗忘的技术遗产

知识图谱的技术基础可以追溯到 1956 年的语义网络（Semantic Networks）和 1980 年代的概念图（Conceptual Graphs）。OWL、RDF、SPARQL——这些标准构成了一个完整的形式化知识表示体系，其精密程度在当时的计算能力下几乎是奢侈品。

深度学习的崛起彻底改变了局面。端到端的神经网络可以自动学习特征表示，无需人工构建本体论（Ontology）。Word2Vec 和 BERT 等模型将"知识"编码为稠密向量，在许多任务上超过了基于规则和符号推理的系统。

知识图谱进入了长达数年的低谷期。

## RAG 带来的转机

RAG（Retrieval-Augmented Generation）的核心思想很简单：**不要让大模型独自承担记忆所有知识的负担，让它学会检索外部知识。**

这一范式最初使用的是向量数据库（Vector DB）——将文本切分成 chunks，编码为向量，存入索引，检索时找到语义最接近的片段。这种方式高效、容错、几乎不需要人工标注。

但向量检索有一个根本局限：**它擅长找"相似的内容"，但不擅长做精确的逻辑推理。**

```
向量检索的问题示例：

问：谁在 2020 年获得了诺贝尔物理学奖？
→ 可能找到包含这些词的段落
→ 但无法推理"2020年"→"获奖年份"→"物理学奖"→"获奖者"的关系链

知识图谱可以表达：
(Roger Penrose, received, Nobel Prize in Physics, 2020)
(Andrea Ghez, received, Nobel Prize in Physics, 2020)
(Reinhard Genzel, received, Nobel Prize in Physics, 2020)

并通过路径查询自动构建答案。
```

## 混合架构的兴起

今天的领先 RAG 系统越来越多地采用**混合检索**策略：向量检索 + 知识图谱检索 + BM25 稀疏检索，多路召回后 rerank 排序。

微软的 GraphRAG、Neo4j 的 LangChain 集成、AWS Neptune 的向量索引——这些工具的涌现说明业界已经意识到，单一检索方式无法满足复杂知识密集型任务的需求。

知识图谱的独特价值在于：

- **多跳推理**：能够沿着关系边进行多步查询，回答需要综合多条知识的问题
- **结构化推理**：支持逻辑运算（AND/OR/NOT）和路径查询
- **可解释性**：答案来自明确的三元组，而非"黑箱向量距离"
- **编辑友好**：新增或修改知识只需要增删边和节点，无需重新训练

## 瓶颈依然存在

知识图谱的构建和维护成本依然是最大的瓶颈。

构建一个高质量的知识图谱需要：领域专家定义本体模型、信息抽取工程师从非结构化文本中识别实体和关系、知识工程师进行质量控制和融合——这个 pipeline 在时间和金钱上的投入，远超简单的向量 chunking。

更重要的是，许多领域的知识本身就是模糊的、冲突的、不断演进的。为这些知识构建静态图谱，既不现实，也无必要。

## 知识图谱的未来

展望未来，知识图谱很可能不会成为一个独立系统，而是作为**神经符号混合系统**（Neuro-Symbolic AI）的核心组件存在。

在这个愿景中，大语言模型负责自然语言理解和生成，知识图谱负责结构化推理和事实校验，两者通过精心设计的接口相互调用。

Google 的 Gemini、OpenAI 的 GPT-4o 都在探索类似的融合路径——让模型能够同时处理符号推理和向量语义，或许是通往更可靠 AI 的必经之路。
